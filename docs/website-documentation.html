1. Platform Overview

Eyad LMS is a lightweight learning management system and public website for Eng. Eyad Mazhar, an American Mathematics instructor in Egypt. It supports American Math, EST, DSAT, and ACT preparation through a simple workflow: the teacher creates accounts, assigns groups, publishes learning content, and students consume that content through a protected portal.

Public website

Introduces the instructor and programs, provides contact options, and routes users to login.

No login required

Admin workspace

Controls accounts, groups, sessions, PDFs, quizzes, previews, and activity.

Admin role

Student portal

Provides assigned sessions, resources, quizzes, review results, and password changes.

Student role

External-first media

Uses Google Drive, YouTube, or direct media URLs so large videos are not stored locally.

Low storage

Core operating principle

Students do not self-register, pay online, or request approval through the website. The teacher creates each account, sends credentials privately, and assigns one or more groups. Group membership determines which active sessions, resources, and quizzes are visible.

Typical lifecycle: create a group, create a student, assign the student to that group, create content for the group, preview it as an admin, then give the student their credentials.

2. Users and Access Model

RoleCan doCannot do
AdminManage admins, students, groups, sessions, resources, quizzes, extra attempts, and activity. Preview active student content without group membership.There is no separate fine-grained permission matrix beyond the admin role.
StudentView assigned active sessions and PDFs, take assigned quizzes, review attempts, and change their password.Cannot register, access admin pages, edit content, or upload files.
VisitorView public pages and submit the public contact form.Cannot access protected learning content.

Authentication behavior

  • Login is shared at public/login.php and accepts username and password.
  • Credentials are verified with PHP password_verify().
  • Successful login stores the user in a PHP session and redirects by role.
  • Logout is handled by logout.php, which clears and destroys the session.
  • Protected pages call the shared requireLogin() helper with allowed roles.

Group access behavior

A student may have a primary group in users.group_id plus additional memberships in user_group_access. The application combines both lists, removes duplicates, and uses the result for access checks. Sessions, resources, and quizzes each have their own group-access table. Content must be active and assigned to at least one matching group.

4. Admin Dashboard Guide

After an admin signs in, the application redirects to admin/dashboard.php. The shared admin navigation contains Dashboard, Students, Admins, Groups, Sessions, Resources, Quizzes, Activity Log, and Logout.

Recommended order for a new class: 1) create the group, 2) create students, 3) assign group memberships, 4) publish sessions and resources, 5) build quizzes, 6) preview the student experience, 7) send credentials.

Dashboard cards

The dashboard gives direct access to every management module and contains a Student View area with previews for Sessions, Quizzes, and Resources. Preview links add ?preview=1; admin preview is intentionally allowed to bypass normal group filtering for active content.

Admin action checklist

  1. Confirm the database connection and create a secure initial admin.
  2. Create meaningful groups with names and levels that students will understand.
  3. Create student accounts with unique usernames and temporary passwords.
  4. Assign each student to the correct primary and additional groups.
  5. Build and order sessions, then assign access groups.
  6. Upload resources and verify each file opens correctly.
  7. Create quizzes with questions, answer keys, limits, and group access.
  8. Use dashboard previews to verify the student-facing listings.
  9. Monitor Activity Log after students start using the site.

5. Student Management

Open admin/students.php from the dashboard. Student records are created manually because enrollment occurs outside the site.

Create a student

  1. Enter the student's name.
  2. Choose a unique username.
  3. Enter a password. The application hashes it before storage.
  4. Add phone and parent phone details if needed.
  5. Select the primary group and add additional group memberships where required.
  6. Set the account to Active, then save.

Manage an existing student

  • Edit: update identity, username, contact details, group assignments, status, and optionally password.
  • Transfer: change the primary group when a student moves cohorts.
  • Deactivate: set status inactive to prevent normal account use or content access.
  • Delete: permanently remove the student record and its additional group-access rows.
Operational practice: use unique usernames, send credentials through a private channel, and prefer deactivation over deletion when historical activity needs to remain understandable.

6. Groups and Access

Open admin/groups.php. Groups are learning cohorts or tracks, not necessarily school grades. Each group has a name and level label.

Good group structure

Use names that make access decisions obvious, such as Morning Batch, EST Intensive, or Advanced 1. The level field can describe the academic track or difficulty.

How access is evaluated

ContentAccess tableStudent result
Sessionlecture_folder_accessVisible when any student group matches an allowed group and the session is active.
PDF resourceresource_group_accessVisible when any student group matches an allowed group and the resource is active.
Quizquiz_group_accessVisible when any student group matches an allowed group and the quiz is active.

Deleting a group clears the matching primary student assignment. Review content access after reorganizing groups so students do not unexpectedly lose or gain material.

7. Sessions and Media

The admin interface calls lectures Sessions. Open admin/lectures.php to create, edit, order, activate, deactivate, assign, or delete them.

Session fields

  • Title: the name displayed to students.
  • Description: optional context or study direction.
  • Media reference: use a direct Google Drive video URL or video ID, YouTube URL, direct video URL, or another external URL. Drive folder links can still be used in the legacy player but are not valid video outline items.
  • Display order: controls listing order.
  • Status: Active or Inactive.
  • Groups: one or more groups that can access the session.

Supported player sources

InputPlayer behavior
Google Drive file link or IDNormalizes to a Drive preview frame.
Google Drive folder link or IDLoads the Drive folder reference.
YouTube watch or short linkConverts to a YouTube embed URL.
Direct MP4, WebM, OGG, M4V, or MOV URLUses the protected media/proxy path as applicable.
Other HTTPS URLRetains it as an external link source when it cannot be classified.

View tracking and deterrents

Opening a valid session records a row in lecture_views. The same student/session pair is not recorded more than once within ten minutes. The player also includes best-effort client-side deterrents for focus loss, visibility changes, screenshot and print shortcuts, context-menu actions, and window opening. These are not DRM and cannot guarantee prevention of recording or screenshots.

Course Outlines and Admin Course Management

After the three SQL migrations in database/ are applied, use admin/courses.php to create courses, assign student groups, assign existing sessions, and link existing PDF resources and quizzes. The existing admin/lectures.php page remains the place to edit a session's title, description, status, order, and its lecture_folder_access permissions.

  1. Create a course and link it to one or more student groups.
  2. Ensure each intended session grants access to at least one of those same groups on the Sessions admin page.
  3. Assign the session to the course from Courses & Outline.
  4. Link existing resources and quizzes to the course; linked records use course-group access, while unlinked records keep their existing group access.
  5. Add or edit ordered items. Use a direct Drive video link or ID for a video item; folder links are rejected. Local PDF paths must remain inside the application.
  6. Activate the course only after its group access and outline are ready.

Existing sessions, resources, and quizzes are not assigned automatically. They remain available through their legacy group-filtered student pages until an administrator assigns or links them to a course. Students see one course and its content at a time. Session-item completion is recorded by the student's explicit action; playback alone does not mark an item complete. Archiving an item hides it from students while preserving its completion history.

Migration safety: back up the database and run course_sessions_modules_migration.sql before course_entities_migration.sql, then apply course_content_links_migration.sql. The second script adds course_modules.course_id with an ALTER TABLE and is a one-time migration, not a repeatable import.

8. PDF Resources

Open admin/resources.php to manage downloadable study material.

Upload requirements

  • Only valid PDF files are accepted.
  • Maximum file size is 20 MB.
  • Both extension and detected MIME type are checked.
  • Files are stored under uploads/pdfs/ with generated filenames.
  • The uploads directory must be writable by the web server.

Resource workflow

  1. Enter a title and optional description.
  2. Choose a PDF file for a new resource. During editing, leave the file empty to keep the existing PDF.
  3. Select one or more access groups.
  4. Choose Active or Inactive.
  5. Save, then verify the resource in the admin preview and student portal.

Replacing or deleting a resource attempts to remove the old file from disk. Students see only active resources assigned to at least one of their groups.

9. Quizzes and Attempts

Open admin/quizzes.php to manage quiz metadata, questions, images, groups, limits, extra attempts, and attempt summaries.

Build a quiz

  1. Enter a quiz title.
  2. Select one or more groups.
  3. Set status to Active when it is ready for students.
  4. Set a time limit in minutes, or use 0 for no limit.
  5. Set maximum attempts, or use 0 for unlimited attempts.
  6. Add question text and four choices for each question.
  7. Select the correct answer.
  8. Optionally upload a JPG, JPEG, PNG, or GIF question image up to 2 MB.
  9. Save and preview the quiz.

Student attempt lifecycle

  1. Start: creates an in_progress attempt with a start time.
  2. Continue: returns the existing attempt for that quiz.
  3. Submit: compares selections with stored correct answers and records score, total, percentage, and selected answers.
  4. Expire: timed-out attempts become expired and receive a zero score.
  5. Review: completed and expired attempts show question-level selections and correct answers.

Attempt rules

  • Only one quiz may be in progress for a student at a time.
  • Attempt counts include submitted and expired attempts, not in-progress attempts.
  • The available limit is the quiz maximum plus the student's extra-attempt allowance.
  • A zero maximum means unlimited attempts.
  • Admins can grant extra attempts to one student for one quiz and save an optional reason.

Quiz review

student/quiz_review.php shows score, percentage, submission time, status, question text, optional image, selected answer, correct answer, and highlighted choices. Students can review only their own attempts; admins can review any non-in-progress attempt.

Open admin/activity_log.php to see recent learning activity. The page combines up to 200 records ordered by action time.

11. Student Portal Guide

Students use the same login page as admins. After login, they are redirected to student/dashboard.php. The student navigation contains Dashboard, Sessions, Resources, Quizzes, and Logout.

Dashboard

The dashboard provides entry cards for Sessions, Resources, and Quizzes, plus a link to the public Contact page.

Sessions

Open Sessions to see active content assigned to any of the student's groups. Select a session to open the responsive player. Access is checked again when the player opens, so a guessed URL does not bypass group restrictions.

Resources

Open Resources to view descriptions and download links for assigned active PDFs. Resources are controlled by group membership.

Quizzes

Open Quizzes to see available work. Start a quiz, answer the four-choice questions, submit before the timer expires when applicable, and use Review Your Quiz Results to inspect the attempt. The listing prioritizes quizzes that have not yet been attempted.

Password change

Students can use student/change_password.php to set a new password. Passwords are hashed before storage.

Student support note: there is no public password-reset email flow. An administrator must assist if a student loses access.

12. Theme and Interface System

The shared visual system lives in assets/css/theme.css. It is applied across public, admin, and student pages through the shared layout partials.

The navy and cyan combination gives the platform a focused academic and technical character while keeping content areas bright.

Surface language

White cards, soft borders, rounded corners, restrained shadows, cyan action states, and a subtle dotted page background create hierarchy without visual noise.

Shared components

  • Navigation: dark navy bars with the circular Eyad logo, brand name, responsive collapse, and role-appropriate links.
  • Buttons: cyan primary actions, outlined secondary actions, rounded corners, bold labels, and lift-on-hover motion.
  • Cards: white surfaces with soft shadows and a slight hover lift.
  • Hero panels: dark navy areas with cyan accents and patterned backgrounds for major dashboard introductions.
  • Tables: responsive horizontal scrolling with readable dark text.
  • Feedback: Bootstrap alerts for success, validation, and error states.
  • Typography: Segoe UI with a clear weight hierarchy and wrapped long text.

Responsive behavior

Bootstrap grid classes, responsive navigation, flexible cards, wrapping controls, responsive tables, and a smaller lecture-player frame support desktop, tablet, and mobile use. The student experience is treated as a first-class mobile workflow.

Shared helpers

  • appBasePath(), appAssetUrl(), and appVersionedAssetUrl() keep links and CSS assets working when the project is installed in a subdirectory.
  • getUserGroupIds() combines primary and additional memberships.
  • requireLogin() enforces session presence and allowed roles.
  • bindPreparedParams() supports dynamic group filters with prepared statements.
  • Shared navigation and footer partials keep branding and Bootstrap loading consistent.

Protected supporting endpoints

student/quiz_time_check.php supports timed quiz checks. student/resource_download.php checks group or course access before serving a PDF. student/proxy_media.php supports protected direct-media handling. student/widevine_license.php is currently a placeholder and is not a production DRM license server.

15. Installation and Configuration

Requirements

  • PHP 8 or newer
  • Apache with PHP enabled
  • MySQL or MariaDB
  • PHP MySQLi, fileinfo, and sessions extensions
  • Writable uploads/pdfs/ and uploads/quizzes/ directories

Local WAMP setup

  1. Place the project at C:\wamp64\www\Eyad_LMS or another Apache web-root folder.
  2. Start Apache and MySQL.
  3. Create the eyad_lms database, or configure another database name.
  4. Configure credentials in db_credentials.php or environment variables.
  5. Ensure upload directories are writable.
  6. Create an active admin user with a password generated by password_hash().
  7. Open http://localhost/Eyad_LMS/.

16. Security and Operations

Implemented protections

  • Password hashing and verification.
  • Session-based login, role checks, and logout.
  • Group checks for student listings and direct content URLs.
  • Prepared statements for database operations.
  • HTML escaping for rendered values.
  • PDF and image extension, MIME, and size validation.
  • Generated randomized upload filenames.
  • Active/inactive checks for accounts and learning content.

Deployment checklist

  • Use HTTPS in production.
  • Keep database credentials private.
  • Use a strong admin password and create only required admin accounts.
  • Verify upload permissions and PHP upload limits.
  • Test each role and each group access path.
  • Back up the database and uploads before major content changes.
  • Review robots.txt and web-server access rules.
Important: browser-level capture deterrents are not a security boundary. The current Widevine endpoint is a placeholder. Production DRM, CSRF protection, rate limiting, recovery workflows, and formal migrations require additional implementation.

18. Current Limitations

  • No student self-registration, online payments, email verification, or email password reset.
  • No gradebook, attendance, certificates, homework submission, discussions, or advanced analytics.
  • No randomized questions, negative marking, or complex grading rules.
  • No device-count enforcement or fine-grained permissions beyond admin/student roles.
  • No complete DRM/license service and no guaranteed recording or screenshot prevention.
  • No formal SQL schema dump, migration runner, or automated backup process.
  • External services such as Web3Forms, Google Drive, and YouTube can affect availability.

Recommended future improvements

Prioritize a formal schema/migration process, CSRF protection, rate limiting, account recovery, automated backups, stronger media protection, progress tracking, richer analytics, and more granular permissions as the platform grows.
